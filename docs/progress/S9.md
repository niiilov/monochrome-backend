## Сделано

- `runner.New(Deps)` и `Run`: загрузка, нормализация, период, флаги `guard.Scan`, тема и извлечение параллельно, кластеризация, оценка, отбор, тексты, `verify.Gate`, запись файлов в `OutDir`.
- Файлы: `digest.md`, `post.txt`, `email_preview.html`, `email.txt`, `journal.csv`, `journal.json`, `run_report.json`.
- Журнал: одна строка на ID в порядке набора, у каждой строки статус. Перед записью вызывается `journal.Validate`. Невыбранные события получают `lower_priority`. Вне периода остаются `out_of_period` и контекстом для проверки обновлений.
- Сбой одного материала пишется в `Error` и не останавливает прогон. Нет клиента LLM: ошибка, код возврата 1, журнал и отчёт всё равно записываются.
- `run_report.json` по разделу 6.6: модель, температура, хэши промптов, конфигурации и набора, время этапов, вызовы, токены, стоимость (`null` и `cost_unavailable`, если цены не заданы), счётчики, verify, хэши артефактов.
- Команда `digest run` в `cmd/digest/cmd_run.go`. Прогресс этапов в stderr, сводка в stdout. `--extra` можно повторять. `--mock` гоняет прогон без сети.
- Параллелизм ограничен `llm.max_concurrency`. Ответы по индексам, поэтому статусы и события при одном и том же mock совпадают.
- E2E на `testdata/synthetic/articles.json` с `llm/mock`: файлы созданы, `journal.Validate` и `verify.CheckFormat` проходят, два прогона дают одни и те же статусы и события.

## Как проверить

```
go test ./internal/runner/ ./cmd/digest/
go vet ./...
go test ./...
go run ./cmd/digest run --dataset testdata/synthetic/articles.json --control-time "2026-11-07T12:00:00+03:00" --out ./out --mock
go run ./cmd/digest check --out ./out
```

Без `--mock` команда берёт `LLM_API_KEY`, `LLM_BASE_URL` и `LLM_MODEL` (файл `.env` читается, если переменная ещё не задана). На этой машине ключа нет, живой прогон не запускался. `--mock` и `digest check --out ./out` прошли.

Контрольное время также принимается как `07.11.2026 12:00`. Пояс без зоны берётся из `period.naive_tz_policy`.

## Нюансы для следующих этапов

- `runner.Deps`: `Config`, `ConfigRaw` (байты `config.yaml` для `config_hash`), `Client`, `Meter`, `Version`, `Now`. Если `Meter` пустой, раннер сам оборачивает клиент. Если метр передан, он уже должен стоять вокруг `Client`, иначе счётчики в отчёте будут нулевыми.
- Раннер дополнительно ставит `llm.WithLimiter` на `llm.max_concurrency`.
- Тексты в файлы берутся из `verify.Gate` (`DigestMD`, `Post`, `EmailText`, `EmailHTML`). Отдельный рендер до гейта не записывается. Время рендера входит в этап `verify`.
- `counts.events` - число событий после отбора, включая невыбранные. В выпуск попадают только `Selected`.
- `control_time` и `period` в отчёте - строки `ДД.ММ.ГГГГ ЧЧ:ММ` через `timeutil.FormatMSK`. `started_at` и `finished_at` - RFC3339 в МСК.
- Хэш набора считается по байтам файлов путей `--dataset` и `--extra` (каталог обходится по отсортированным именам). Хэш конфигурации - байты файла, без секретов.
- Повторный ID не получает вторую строку журнала: пометка остаётся в трассе первой записи. Так договорился S2, `Validate` не принимает две строки с одним ID.
- Ошибка классификации темы: статус `исключён`, текст «Не удалось определить тему материала», `reason_code` пустой. Отдельного кода в разделе 7 нет.
- Если `summarize.Items` падает целиком, раннер подставляет шаблонные пункты и идёт в гейт. Пакет summarize при одном сбое не отдаёт уже готовые пункты.
- `--mock` (`runner.NewOfflineClient`) детерминированный и без сети. Рекламу узнаёт по словам «скидка», «вебинар», «промокод», «специальное предложение». Остальные статьи со словарными совпадениями считает темой. События не склеивает, оценки пустые, текст пункта шаблонный. Для содержательного выпуска нужен живой клиент без `--mock`.
- Прогресс CLI печатает этап и счётчик. Подробные пометки пайплайна остаются в `journal.json`, на консоль Info не выводится.

## Открытые вопросы

- `period.hours` по-прежнему не читается: окно всегда 24 часа, как зафиксировал S2. Если длина должна браться из конфига, нужна ветка `contract-period-hours`.
- Для сбоя темы нет кода причины. Пока строка исключена, код пустой, объяснение в `reason` и `error`. Если жюри потребует код из раздела 7, его нужно добавить отдельной веткой контракта.
- `--mock` не повторяет редакторские решения учебной выборки. Это запасной режим без ключа, не замена модели на защите.
