# S13a: Звёздочка: ИИ-критик и замер эффекта

Владелец: B
Статус: выполнен
Ветка / коммит: s13a-critic / (после коммита)

## Сделано

- `internal/critic`: промпт `critic_check` разбирает утверждения пересказа, вердикты `supported` / `unsupported` / `uncertain` с цитатой и причиной. Промпт отдельный от генератора.
- `critic.GateCritic` реализует `verify.Critic`; `unsupported` -> `error` (ретрай события), `uncertain` -> `warn`.
- `verify.Options`: поля `CriticEnabled` и `Critic`. При выключенном флаге или `Critic == nil` поведение гейта как до S13a.
- `digest eval-critic` (`cmd/digest/cmd_evalcritic.go`): сравнение с критиком и без на учебном пересказе и на синтетике с подсаженными смысловыми ошибками; отчёты `docs/critic_eval.json` и `docs/critic_eval.md`. По умолчанию `--mock`.
- Тесты без сети на `llm/mock`.

## Как проверить

```
go vet ./...
go test ./...
go test ./internal/critic/... ./internal/verify/ -run Critic
go run ./cmd/digest eval-critic --mock --out docs
```

Прогон без `--critic` / с `verify.critic_enabled: false` не меняет результат: раннер по-прежнему не передаёт критика в гейт.

## Нюансы для следующих этапов

- Подсаженные ошибки в eval - смысловые (без новых чисел, URL и кавычек), иначе детерминированный гейт снимает их раньше критика.
- Живой замер: `digest eval-critic --live`. Модель критика берётся из `critic.model`, если задана, иначе `llm.model`.
- Включение в основном пайплайне: раннер должен передать `verify.Options{CriticEnabled: cfg.Verify.CriticEnabled, Critic: critic.GateCritic{Client: ...}}` и флаг `--critic` в `cmd_run.go` (владелец A).
