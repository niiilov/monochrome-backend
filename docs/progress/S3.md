# S3: LLM-клиент, промпты, защита от инъекций

Владелец: B
Статус: выполнен
Ветка / коммит: s3-llm / S3: llm client, prompts, and injection guard

## Сделано

- `internal/llm`: `Client`, `Request`, `Response`, OpenAI-совместимый HTTP-клиент (`/v1/chat/completions` или `/chat/completions`, если у base URL уже есть путь). JSON Schema в `response_format`, при отказе сервера повтор без схемы и строгий разбор. `seed` убирается, если сервер отвечает 400 с упоминанием seed.
- Обёртки `WithRetry` (429, 408, 5xx, таймаут, сеть, экспонента и Retry-After), `WithLimiter`, `Meter`, `WithCache`. Кэш по хэшу запроса выключен, пока `llm.cache_dir` пуст. Попадание в кэш не считается вызовом модели.
- `CompleteJSON`: `DisallowUnknownFields`, снятие markdown-обёртки, до 2 повторов с текстом ошибки валидации.
- `internal/llm/mock`: правила по задаче и подстроке, очередь, `When` / `Queue` / `Once` / `Reply` / `Fail`, счётчики. Пример в doc-комментарии и в `ExampleClient_When`.
- `prompts/embed.go` и загрузчик `internal/prompts`: `Render`, `Hash`, версия из `{{/* version: N */}}`. `common_rules` подключается ко всем промптам.
- `internal/guard`: `WrapUntrusted`, `Scan`, `CheckOutput`.
- `testdata/injections/cases.json`: 18 вариантов (заголовок, текст, URL, CSV-ячейка, русский и английский).
- Команда `digest llm-ping` в `cmd/digest/cmd_llmping.go`. Ключ не печатается. Локальный `.env` читается, если переменная ещё не задана, и не перетирает окружение.

## Как проверить

```
go test ./internal/llm/... ./internal/guard/... ./internal/prompts/...
go vet ./...
go test ./...
go run ./cmd/digest llm-ping
```

`llm-ping` без `LLM_API_KEY`, `LLM_BASE_URL` или `LLM_MODEL` завершается с кодом 2 и списком того, чего не хватает. Ключ в этот список не попадает.

На этой машине нет gcc, поэтому `go test -race` не запускается (`-race requires cgo`). Параллельный тест `Meter` есть и проходит без детектора гонок.

## Нюансы для следующих этапов

- Стек `llm.New`: кэш, затем meter, затем retry, затем limiter, затем HTTP. Неуспешный вызов в meter не попадает. Цена считается только если заданы оба прайса, иначе `cost = null` и `cost_unavailable = true`.
- `CompleteJSON` повторяет только невалидный JSON. Сетевые повторы делает `WithRetry`. Лишние поля JSON - ошибка, они не отбрасываются.
- HTTP-клиент отказывается от промпта длиннее `llm.max_input_chars` (считаются руны system и user).
- Тесты внутри пакета `llm` не могут импортировать `llm/mock` (цикл импорта). Чужие пакеты импортируют `cyberdigest/internal/llm/mock` как обычно.
- `prompts.Render` сам дописывает общие правила в system, если их там ещё нет. Шаблон `common_rules` тоже доступен как `{{ template "common_rules" . }}`. Версии system и user должны совпадать. `Hash` - SHA-256 всех `*.tmpl`.
- Коды `guard.Scan`: `ignore_previous`, `forget_previous`, `system_prompt`, `role_override`, `send_to`, `forward`, `put_first`, `email`, `html`, `markdown`, `base64`. Срабатывание не удаляет текст.
- `CheckOutput`: `url`, `email`, `service_phrase`. Пустая карта разрешений не разрешает ничего. У URL допускается хвостовой слэш, почта сравнивается без учёта регистра.
- `WrapUntrusted` экранирует `<` в тексте, поэтому закрывающий тег внутри статьи не обрывает блок.
- Для Gemini AI Studio base URL: `https://generativelanguage.googleapis.com/v1beta/openai` (без лишнего `/v1`). На этот хост клиент дополнительно ставит заголовок `x-goog-api-key`. Ключ по-прежнему только из окружения.
- Локально для проверки взята модель `gemini-3.5-flash`: `digest llm-ping` печатает модель, токены и время. `gemini-2.0-flash` и `gemini-2.5-flash` для этого ключа закрыты. `gemini-3.8-flash` и `gemini-flash-latest` на момент проверки отвечали 503 (высокая нагрузка).

## Открытые вопросы

- Какую модель зафиксировать для сдачи. Сейчас рабочий бесплатный вариант для этого ключа - `gemini-3.5-flash`. Имя модели остаётся в `LLM_MODEL`, не в `config.yaml`.
- На Windows без gcc приёмка `go test -race` здесь не выполнена. На Linux с CGO её нужно прогнать отдельно.
- Ключ был вставлен в чат. В репозитории его нет, он только в локальном `.env`. Его стоит отозвать и выпустить новый.

## Передачи второму участнику

- `cmd/digest/main.go` не менялся. Команда зарегистрирована в `init()` файла `cmd_llmping.go`.
