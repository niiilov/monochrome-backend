# S2: Время, период и журнал

Владелец: A
Статус: выполнен
Ветка / коммит: s2-time-journal / S2: parse period and write journal

## Сделано

- `timeutil.MSK` - `Europe/Moscow` через `time/tzdata`.
- `ParseDate` разбирает ISO 8601 со смещением и `Z`, `ДД.ММ.ГГГГ ЧЧ:ММ` (запятая или пробел), `2 ноября 2026, 14:05`, RFC1123, Unix (10 цифр - секунды, 13 - миллисекунды). Подтвержденное время всегда в МСК.
- Только дата, пустая строка и неразборчивая строка дают `nil` и русскую пометку. Это будущая причина `date_unconfirmed`.
- Дата без пояса: `assume_msk` (и пустая политика) оставляет часы как МСК и пишет пометку в трассу. `reject` дату не подтверждает. Хвост `МСК` / `MSK` / `UTC` / `GMT` считается явным поясом.
- `NewPeriod` строит окно `(контрольное время минус 24 часа, контрольное время]`. `Contains` живет в `domain` (так зафиксировал S0): `t > start && t <= end`.
- `FilterPeriod` возвращает четыре значения: в периоде, вне периода, без подтвержденной даты, карта пометок `id -> текст` для стадии `period`. Входной срез не меняется.
- `journal.Journal` потокобезопасен: `Add`, `Set`, `Note`, `Get`, `Entries`. Одна строка на ID, порядок первого появления.
- Тексты причин из раздела 7: `journal.Text` и `journal.StatusFor`.
- `Validate` требует ровно одну строку на каждый ID, статус только из трех значений, у `объединён` есть группа.
- `WriteCSV` пишет UTF-8 без BOM, столбцы строго `id,status,group,reason,error`, `encoding/csv`, порядок строк как порядок наполнения. `WriteJSON` пишет тот же порядок с `reason_code` и расширенными полями.

## Как проверить

```
go test ./internal/timeutil/... ./internal/journal/...
make vet test
```

Границы покрыты тестом: ровно start исключен, start+1с включен, ровно end включен, end+1с исключен, те же границы в UTC и `+05:00`, дата без пояса, только дата. `Validate` в тесте ловит пропущенный ID и статус `включен` без буквы ё.

## Нюансы для следующих этапов

- Раннер (S9) не подключался. Фильтр сам статусы журнала не ставит.
- `out` нужно сохранить как контекст проверки обновлений. В дайджест эти материалы не входят: позже статус `исключён`, код `out_of_period`.
- `unconfirmed` тоже `исключён`, код `date_unconfirmed`. Текст причины берется из `journal.Text`, а пометка `ParseDate` дополнительно кладется в трассу: `journal.Note(id, "period", note)`.
- При `assume_msk` материал не считается неподтвержденным. Он попадает в `in` или `out`, пометка только в `notes`.
- Если у статьи уже заполнен `PublishedAt`, сырая строка не разбирается. Время приводится к МСК.
- `FilterPeriod` не смотрит на `ReadError`. Строки с ошибкой чтения в фильтр передавать не нужно: причина у них уже есть.
- `NewPeriod` не читает `period.hours`. Ширина окна всегда 24 часа, как в разделах 5.2 и 7.
- Наполнять журнал нужно в порядке набора: `WriteCSV` и `WriteJSON` пишут порядок первого `Add` или `Set`. Повторный `Set` строку не переставляет.
- `Note`, пришедший до строки, не теряется: он приклеивается к `Trace` в момент `Add` или `Set`.
- Колонка `error` не входит в шаблон причины. Для `read_error` и `source_unavailable` текст ошибки передает вызывающий.
- Календарная дата для строки «Источники» - `02.01.2006` в `timeutil.MSK`. `FormatMSK` добавляет еще и часы. `FormatPeriod` уже дает `06.11.2026 12:00 - 07.11.2026 12:00 МСК`.
- Ветка S1 в `main` не слита. Разбор дат от нее не зависит: строки из будущего синтетического набора (`07.11.2026, 11:45`, `6 ноября 2026, 19:30`, `07.11.2026`, `Z`, RFC1123 `+0300`, Unix `1794029400`, ISO без пояса) покрыты тестами здесь.

## Открытые вопросы

- `period.hours` в конфиге может отличаться от 24, но окно S2 всегда 24 часа. Если длина должна браться из конфига, нужна ветка `contract-period-hours` до S9.
- S1 на ветке `s1-ingest` хочет две строки CSV на один повторившийся ID. Этот журнал хранит одну строку на ID, и `Validate` считает вторую лишней. До S9 оставить одну строку: в статьях первая запись, повтор в отдельную строку с тем же ID не класть.

## Передачи второму участнику

- Период и разбор дат уже в `timeutil`. Свои форматы времени для дайджеста, поста и письма не заводить: `MSK`, `ParseDate`, `NewPeriod`, `FilterPeriod`, `FormatMSK`, `FormatPeriod`.
- Статусы журнала только `включён`, `объединён`, `исключён`, с буквой ё. Формулировки причин брать из `journal.Text`.
- `journal.csv`: ровно столбцы `id,status,group,reason,error`, UTF-8 без BOM. Перед записью вызывать `Validate`.
- Четвертое значение `FilterPeriod` - пометки трассы стадии `period`. При политике `assume_msk` это не повод исключать материал.
- Список вне периода не выбрасывать. Он нужен как контекст обновлений, в текст выпуска не входит.
