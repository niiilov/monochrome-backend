# S13b: Звёздочка: живой сбор и устойчивость

Владелец: A
Статус: выполнен
Ветка / коммит: s13b-live / S13b: add optional live collection and hard-input checks

## Сделано

- `internal/ingest/live`: плагины `rss` (gofeed), `html` (goquery) и `api` (JSON). Файл `sources.yaml` в корне: SecurityLab, Хакер, CNews, ComNews, Positive Technologies.
- Сбор уважает `robots.txt`, таймаут, повторы, User-Agent и файловый кэш. Недоступный источник не останавливает прогон: строка журнала `source_unavailable`, текст «Источник недоступен».
- Записи получают поля набора (`id`, `title`, `text`, `source`, `url`, `published_at`) и идут в общий пайплайн. Идентификатор вида `live-<источник>-<хэш>`.
- Флаг `--live` у `digest run` включает сбор в памяти (`live.enabled`). `--sources` подменяет файл источников. `config.yaml` не менялся, без флага ветка сбора не выполняется.
- Длинный текст живой страницы (больше 8000 знаков) режется `normalize.Chunks`, из каждой части берется короткий фрагмент, хвост сохраняется (`live.FoldParts`). Это не вызов модели.
- Устойчивость на `testdata/hard`: пустой файл, чужая кодировка, нулевые байты, статья больше 1 МБ, поле нулевой длины (`zero-fields.json`), огромные числа (`huge.json`). Загрузка не падает.
- Тесты ходят только в записанные RSS, HTML и JSON. HTTP в тестах поднимается локально (`httptest`), наружу запросов нет.
- Зависимости: `github.com/mmcdole/gofeed` v1.3.0, `github.com/PuerkitoBio/goquery` v1.10.2.

## Как проверить

```
go test ./internal/ingest/... ./internal/runner/ ./cmd/digest/
go run ./cmd/digest run --dataset testdata/synthetic/articles.json --control-time "2026-11-07T12:00:00+03:00" --out ./out --mock
go run ./cmd/digest run --dataset testdata/synthetic/articles.json --control-time "2026-11-07T12:00:00+03:00" --out ./out-live --mock --live --sources testdata/live/sources.yaml
```

Прогон без `--live` не содержит строк `live-` и «Источник недоступен». Прогон с `--live` на `testdata/live` пишет пять записей и строку `source_unavailable` для отсутствующего файла.

События из этих фикстур проверяет `TestLiveFixturesProduceEvents`: скриптованный `llm/mock`, в выпуске есть блок `## 1.`, недоступный источник остается в журнале. `go test ./internal/ingest/...`, `./internal/runner/` и `./cmd/digest/` зеленые.

`go test ./internal/api` на этой Windows-машине падает еще до S13b: тест вклеивает путь с обратными слешами в JSON. Пакет `api` не менялся.

## Нюансы для следующих этапов

- Сбор включается только если `config.Live.Enabled == true`. Флаг `--live` выставляет это поле у уже загруженного конфига. Поле в `config.yaml` по-прежнему `false`.
- Кэш: каталог `live.cache_dir`, срок 1 час (в замороженном конфиге отдельного поля нет). Пустой каталог значит «без кэша». Ответ больше 8 МБ не принимается.
- `robots.txt`: 401 и 403 запрещают сайт, прочая ошибка чтения robots не блокирует источник. Для файла на диске robots не запрашивается.
- Повтор: `live.max_retries` дополнительных попыток на 429, 408, 5xx и сетевой ошибке. Пауза 200 мс, дальше удваивается, потолок 2 с.
- `digest run --mock` не доводит живые записи до события. Встроенный offline-клиент ищет слова «скидка», «вебинар», «промокод» во всем промпте, а они есть в system-шаблоне `classify_topic`. Поэтому классификатор помечает материал как рекламу. Для проверки событий нужен `llm/mock` со скриптом, как в тесте раннера.
- Текст набора `testdata/hard/large.json` в пайплайн по-прежнему попадает целиком. Сжатие по частям применяется к длинным страницам живого сбора и вызывается из теста. Этапы темы, извлечения, кластера и оценки по-прежнему отдают модели первый чанк.

- Адреса, которые стоит сверить перед боевым `--live`:

  - Хакер: `https://xakep.ru/feed/`
  - CNews: `https://www.cnews.ru/inc/rss/news.xml`

  - Positive Technologies: `https://www.ptsecurity.com/api/news`, список в поле `items` (публичный JSON API не подтвержден, при ошибке источник станет `source_unavailable` и прогон продолжится)

## Передачи второму участнику

- Пакет `summarize` по-прежнему не режет длинную статью на части. Если нужно суммировать чанки моделью и склеивать ответ, это зона B. Живой сбор до пайплайна сам складывает длинную страницу в короткий текст без модели.
- `internal/api`: на Windows `TestPreviewExportAndAllowlist`, `TestSendWhileRunningIsConflict` и `TestRealRunnerOnSynthetic` отвечают `400 некорректный JSON`. `fixture` дает путь с `\`, а тест вставляет его в JSON-строку (`\t` в `\testdata` и неизвестная последовательность `\s`). На Linux путь со слешами `/` и тест, скорее всего, зеленый. Код API не менялся.
