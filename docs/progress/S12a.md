- Требования README зафиксированы ниже.

Требования README организаторов:

- В прогон передается файл набора, не каталог.
- Поля: `id`, `title`, `text`, `source`, `url`, `published_at`.
- Пустое поле: пустая строка, `null`, `N/A`, `не заполнено`.
- Дата: RFC3339, `ДД.ММ.ГГГГ ЧЧ:ММ` или только дата. Дату без времени подтвердить нельзя.
- Пустой id и повтор id - ошибка чтения, остальные записи обрабатываются.
- `check_digest.py` смотрит каталог результата. `digest.md`: заголовок с периодом и контрольным временем, не больше пяти блоков `## N.`, поля `Суть:`, `Последствия:`, `Источники:`, `Обоснование:`, не длиннее 4 000 знаков без URL, без длинного тире и без блока «Не вошли».
- `post.txt` не длиннее 2 000 знаков без URL.
- `journal.csv`: UTF-8 без BOM, столбцы `id,status,group,reason,error`, одна строка на id. Статусы: `включён`, `объединён`, `исключён`. У `объединён` группа заполнена.
- Нужен `email_preview.html` или `email.txt`.
- Код выхода 0 и строка `формат в порядке`. Скрипт не оценивает выбор событий.

## Как проверить

```
go test ./internal/extract/ ./internal/cluster/ ./internal/rank/ ./internal/topic/ ./internal/runner/
go run ./cmd/digest run --dataset testdata/train/publications.json --control-time "2026-11-07T12:00:00+03:00" --out ./out
python tools/check_digest.py ./out
```

Живой прогон без прокси: переменные `LLM_PROXY` и `LLM_PROXY_FILE` должны быть пустыми до старта, иначе `digest run` прочитает их из `.env`.
