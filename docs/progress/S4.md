## Сделано

- `topic/dictionary.go`: словарь Приложения 2 по группам. Русские слова сравниваются по основе (усечение окончаний), английские термины и аббревиатуры (ИБ, КИИ, ПДн, ГИС, ФСТЭК, DDoS и остальные короткие обозначения) совпадают только как целые слова. Регистр и буква ё не важны.
- Слабые термины: «база данных», «учётная запись», «сертификат», «пароль», «токен», «backup», ведомства (ФСТЭК, ФСБ, Роскомнадзор, Минцифры, НКЦКИ, ГосСОПКА). Сами по себе тему не доказывают, но вызов модели не отменяют.
- `Prefilter` и `Scan` возвращают совпадения. `HasStrong` отличает сильное совпадение от набора одних слабых.
- Промпт `prompts/classify_topic.*.tmpl`. JSON: `is_on_topic`, `is_advertising`, `confidence`, `reason`. Реклама без события исключается даже при совпадении слов. Анонс с реальным инцидентом рекламой не считается.
- `Classify`: нет совпадений в заголовке и тексте, модель не вызывается. Иначе текст режется `normalize.Chunks` (бюджет `llm.max_input_chars` минус 2000 рун на промпт и обертку) и передается только через `guard.WrapUntrusted`. `MatchedTerms` заполняет код.
- `Decide`: дальше идет только `is_on_topic && !is_advertising`. Иначе `off_topic` или `advertising` с текстом из `journal.Text`. При обоих флагах побеждает реклама. Свободный текст модели правило не меняет.

## Нюансы для следующих этапов

- Журнал этот этап не пишет. Раннер вызывает `Classify`, кладет `TopicResult` в `JournalEntry.Topic` и при `!Decide(res).Pass` ставит статус и причину из `Decision`.
- Пропуск модели дает `IsOnTopic=false` и причину «нет терминов». `Decide` превращает это в `off_topic`.
- Слабое совпадение все равно идет в модель. Автоматически по теме статья не ставится.
- К фразам приложения добавлены словоформы и синонимы коротких новостей: «атака», «инцидент», «угроза», «уязвимость», «утечка», «шифровальщик», «выкуп», «вредонос», «антивирус», «скиммер», «поддельный сайт», английские password, token, certificate. Каноническое имя в `MatchedTerms` остается именем пункта словаря.
- Бюджет текста для модели: `config.Default().LLM.MaxInputChars - 2000`. Предфильтр смотрит полный текст, в промпт уходит первый кусок.
- syn-24 («Сбой у оператора», тело `N/A`) не содержит терминов, модель не вызывается, причина `off_topic`. Если раннеру нужна причина `insufficient_text`, проверку длины текста надо делать до `Classify`.
- Дефис режет токен. «apt-get» дает отдельное слово «apt» и может совпасть с аббревиатурой APT. Решение все равно за моделью.

## Открытые вопросы

- Короткие леммы «атака» и «инцидент» шире буквального списка приложения. Они нужны, чтобы заметка без слова «кибератака» не отбрасывалась молча. Если на учебном наборе организаторов будет много ложных вызовов, леммы можно сузить, не меняя контракт `Classify`.

## Передачи второму участнику

- Промпт `classify_topic` ожидает JSON только с полями `is_on_topic`, `is_advertising`, `confidence`, `reason`. Лишнее поле `CompleteJSON` отвергает. `matched_terms` в ответ модели класть не нужно: их проставляет словарь.
- Общие правила по-прежнему дописывает `prompts.Render`. Шаблон `common_rules` не менялся.
- В пакетах `llm`, `guard` и `prompts` правок нет.
