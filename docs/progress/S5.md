# S5: Извлечение событий и кластеризация

Владелец: A
Статус: выполнен
Ветка / коммит: s5-events / S5: extract mentions and cluster events

## Сделано

- Промпты `extract_events`, `cluster_confirm`, `update_check`. В них нет порогов, получателей и прочих настроек. Текст статьи передается только через `guard.WrapUntrusted`.
- `extract.Mentions`: 1..N упоминаний, ID `M-<articleID>-<n>`. Цитата сохраняется только если после схлопывания пробелов она находится в тексте или заголовке; в событие кладется исходный фрагмент статьи. Иначе факт отбрасывается, в трассу пишется предупреждение. Оговорка, которой нет в статье, тоже отбрасывается.
- Достаточность решает код: `ingest.min_text_chars` (по умолчанию 200) и минимум 2 законченных предложения. Если код говорит «мало», `sufficient_text` модели не принимается. Короткий текст не становится событием.
- `cluster.Build`: пары по сущностям (включая CVE), числам, датам и лексическим биграммам. Порог `cluster.similarity_threshold`, не больше `max_pairs_per_article` пар на статью. Пара склеивается только после `cluster_confirm`. ID `E01...` назначаются по дате публикации, затем по ID статьи и упоминания.
- `PrimaryArticleID`: сначала `vendor` или `regulator`, среди них более ранняя публикация. Перепечатка (`is_reprint`) не увеличивает `IndependentSources`. Ссылка такой статьи в событии остается.
- Расхождение чисел или дат, если ни одно множество не вложено в другое, пишется в `Event.Conflicts` вместе с конфликтами модели. Версия не выбирается.
- Статьи из `RunState.Context` только контекст. Совпадение с событием заполняет `ContextArticleIDs` и вызывает `update_check`. Пустой список новых фактов исключает свежую статью (`stale_no_new_facts`) и убирает ее из события. Непустой список оставляет событие и пишет `NewFacts`. Статья вне периода всегда «исключён», даже если событие на нее ссылается.
- Упоминание с `references_earlier` и пустыми `new_facts`, если контекстной статьи в наборе нет, тоже `stale_no_new_facts`.
- `cluster.ApplyJournal`: представитель самого раннего события «включён», остальные участники «объединён» с той же группой. Несколько событий у одной статьи: группа равна первому событию, остальные перечислены в причине. Сбой одного вызова модели не останавливает этап: пара не склеивается, текст ошибки кладется в `Result.Errors`.

## Как проверить

```
go test ./internal/extract/... ./internal/cluster/...
make vet test
```

На mock: 3 статьи об одном инциденте дают одно событие и все ссылки; старая статья вне периода, свежая с новым фактом и свежая без факта получают статусы «исключён» / «включён» / «исключён»; разные числа и даты остаются в `Conflicts`; статья с двумя упоминаниями дает два события; перепечатка заявления не увеличивает `IndependentSources`. Повторный `Build` возвращает те же `E01...`. Каждая оставшаяся цитата является подстрокой заголовка или текста. В промптах нет длинного тире.

## Нюансы для следующих этапов

- Трасса: `extract.WithNoter(ctx, journal)` перед `Mentions` и `Build`. `cluster` пишет в тот же контекст, стадия `cluster`. Строка журнала должна уже существовать, иначе `journal.Note` держит пометку до `Add` или `Set`.
- `ApplyJournal` решает судьбу каждого ID из переданных списков периода и контекста. Сюда нельзя класть статьи, которые уже исключены раньше (вне темы, реклама, ошибка чтения): причина будет перезаписана.
- «включён» на этом этапе значит представителя кластера, не место в выпуске. Код причины `selected`, текст шаблона без обоснования: «Событие вошло в выпуск». S6 обязан заменить его на обоснование или на `lower_priority`.
- Порог знаков и бюджет входа берутся из `config.Default()`, не из загруженного файла: у `Mentions` и `Build` нет аргумента с полным конфигом. В `Build` передается только `config.Cluster`.
- В модель уходит первый кусок `normalize.Chunks`. Проверка цитаты идет по полному тексту и заголовку.
- Контекст сопоставляется тем же порогом сходства, без `cluster_confirm`. Ошибка `update_check` не исключает статью: она остается, текст ошибки в `Result.Errors`.
- Числовой конфликт не ставится, если числа одной статьи вложены в числа другой (обновление добавило цифру). Конфликт ставится, когда множества расходятся в обе стороны.
- Пустой ответ извлечения или упоминание без подтвержденных цитат не создает событие. Такая статья в списке периода получает `insufficient_text`.

## Открытые вопросы

- Минимум предложений для пересказа равен 2. В замороженном конфиге такого поля нет. Если на учебном наборе длинная однофразовая заметка будет зря отбрасываться, порог можно снизить в коде, не меняя контракт `Mentions`.
- `Mentions` не видит `min_text_chars` из загруженного `config.yaml`, только значение по умолчанию 200. Сейчас оно совпадает с файлом. Если порог нужно менять без правки кода, понадобится ветка `contract-extract-config`.

## Передачи второму участнику

- Новые шаблоны: `extract_events`, `cluster_confirm`, `update_check`. `prompts/embed.go` не менялся, `*.tmpl` подхватываются сами. Общий блок по-прежнему дописывает `prompts.Render`.
- Лишние JSON-поля `CompleteJSON` отвергает. `extract_events`: объект с `mentions` (title_draft, facts.text, facts.quote, affected, consequences, hedges, entities, is_company_statement, is_reprint, reporter, references_earlier, new_facts, sufficient_text). `cluster_confirm`: `same_event`, `shared_entities`, `reason`, `conflicts` (field, description, article_ids). `update_check`: `new_facts`.
- Цитата должна быть непрерывным фрагментом статьи. Пересказ вместо цитаты код выбрасывает.
- В пакеты `llm`, `guard`, `prompts` (загрузчик) и `embed.go` правок нет.
