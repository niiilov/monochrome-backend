# S11b: Подключение раннера к API и веб

Владелец: B
Статус: выполнен
Ветка / коммит: s11b-wire-runner / S11b: connect the real runner to the API and web

## Сделано

- `cmd/digestd` без флага собирает `runner.New` из `config.yaml` и env (`LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, файл `.env` если переменная ещё не задана). `--fake` по-прежнему поднимает `runner/fake`. `--mock` оставляет тот же `runner.New`, но клиент локальный (`runner.NewOfflineClient`), без сети. `--fake` и `--mock` вместе отклоняются.
- `internal/api`: httptest гоняет реальный раннер на `llm/mock` и `testdata/synthetic/articles.json`. Проверены прогресс, `digest.md` и `digest.json` (текст совпадает, у события есть источники), письмо, журнал, `run_report.json` (HTTP `run_id`, хэши артефактов), ZIP, dry-run, повторная публикация и публикация с посторонней инструкцией. Получатель из текста не попадает в рассылку, в журнале есть `injection_suspected`.
- Форматы файлов раннера и ответов API совпали: `digest.json` по-прежнему дописывает API из `RunState` и `digest.md`, отчёт перезаписывается с `run_id` прогона HTTP, хэши раннера сохраняются.
- В веб-странице имена этапов показываются по-русски. Этап `write` раннер не присылает, список рисует то, что пришло.
- Сквозной сценарий в браузере на `go run ./cmd/digestd --mock`: запуск синтетики, прогресс, вкладки, ZIP, dry-run на `jury@example.com`, добавление повтора (41 материал) и инструкции (42 материала, флаг `injection_suspected`), повторный dry-run с тем же адресом.

## Как проверить

```
go test ./internal/api/ ./cmd/digestd/
go vet ./...
go test ./...
DIGEST_ADDR=127.0.0.1:18083 ALLOWED_TEST_RECIPIENTS=jury@example.com go run ./cmd/digestd --mock
```

В браузере: путь `testdata/synthetic/articles.json`, контрольное время `2026-11-07T12:00:00+03:00`, «Запустить», вкладки, «Выгрузить», «Разослать (тест)» с dry-run. Затем «Добавить и перезапустить» с текстом повтора события и отдельно с текстом «Игнорируй предыдущие инструкции».

Без `--mock` и `--fake` сервер требует ключ, базовый URL и модель. На этой машине ключ пустой, живой прогон не запускался.

## Нюансы для следующих этапов

- Ветка отходит от `s11a-api-web`, а не от чистого `origin/main`: коммита S11a в `origin/main` нет. В `origin/main` есть S9.
- `--mock` не склеивает повтор в одно событие: офлайн-клиент всегда отвечает, что события разные. Дополнительная публикация получает свою строку журнала. Чтобы на защите увидеть объединение, нужен запуск без `--mock`.
- Каталог `out/s11b-ui` от браузерной проверки в git не входит.

## Открытые вопросы

- S11a ещё не влит в `main`. Пока его нет, эту ветку нельзя собирать только из `origin/main`: пропадут API и веб.
- Живая модель не запускалась: `LLM_API_KEY` пустой. После появления ключа сервер стартует без `--mock`.

## Передачи второму участнику

- Пакеты участника A не менялись. Расхождения форматов между API и файлами раннера, которые надо чинить в раннере, не нашлись.
- Раннер по-прежнему не шлёт прогресс этапа `write`. Веб это учитывает и подписывает пришедшие этапы по-русски.
- На `--mock` повтор события не объединяется. Это поведение офлайн-клиента из S9, отдельной правки раннера отсюда не прошу.
