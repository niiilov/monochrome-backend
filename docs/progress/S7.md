# S7: Тексты и рендер

Владелец: B
Статус: выполнен
Ветка / коммит: s7-texts / S7: write digest items, post, and email

## Сделано

- Промпты `write_digest_item` и `write_post`. На вход пункта: факты с цитатами внутри `guard.WrapUntrusted`, оговорки, конфликты, роли источников. Полный текст статьи в промпт не кладётся. JSON: `title`, `essence` (2-3 предложения), `consequences`, `hedge_note`.
- `summarize.Items`: не больше 5 событий, при любом `Selected` остальные пропускаются, `Rank > 0` задаёт порядок. Вызовы параллельные, не больше 4 сразу. `retryHints` - это заметки по ID события. Если черновик длиннее 4000 знаков без URL, длинные пункты запрашиваются ещё один раз.
- Источники собирает код, не модель. `vendor` и `regulator` первые, роль «первичный источник». Перепечатка получает роль «перепечатка». Дата - первые 10 символов `timeutil.FormatMSK`. `ContextArticleIDs` в список не входят.
- `summarize.ShortItems` сжимает пост из полей `DigestItem`, не из готового markdown. URL копируются из `Sources`. Если черновик длиннее лимита, модель вызывается ещё раз, затем обрезаются хвостовые предложения.
- `render.Digest` пишет формат раздела 6.1. `render.CheckFormat` проверяет заголовок, строку «Событий в выпуске», блоки `## N.` и четыре поля. Длинное тире заменяется. При переполнении сначала сокращаются обоснование и лишние предложения, источники не удаляются.
- `render.Post`, `render.EmailText`, `render.EmailHTML` читают ту же `DigestModel`. Письмо: тема, период, полный дайджест. HTML через `html/template`.
- Ноль событий: «Подходящих событий за период нет» и причина из `Shortfall`, одинаково в дайджесте, посте и письме. Блоков `## N.` нет. `NotIncluded` в `digest.md` не попадает.

## Нюансы для следующих этапов

- Нет последствий: ровно `В источнике сведения о последствиях не приведены.` (`summarize.NoConsequences`). Пустая строка, «нет данных» и близкие формулировки заменяются на эту фразу.
- `hedge_note` дописывается в конец `essence`, если этой оговорки там ещё нет. В `DigestItem` отдельного поля нет.
- Пустое обоснование события: «Обоснование отбора в данных события не приведено.» Рабочее обоснование берётся из `Event.Rationale`, S6 его должен заполнить.
- `Shortfall` при 1-4 событиях дописывается после «Событий в выпуске: N.». Если поле пустое, пишется «Подходящих событий меньше пяти.» При 5 событиях `Shortfall` в файл не попадает.
- `Empty == true` убирает пункты, даже если слайс не пустой.
- `render` заново ставит номера 1..N по порядку модели. `ShortItems` нужно вызывать на модели, где `N` уже 1..N. `Items` это делает.
- Строка источника: `Название (роль), ДД.ММ.ГГГГ, URL, ID: x`. Несколько источников через `; `. Первичный источник стоит первым.
- Пост: строка периода, затем `N. Заголовок`, сжатый текст, каждый URL с новой строки. URL из ответа модели, которых нет в `Sources`, выбрасываются.
- Текст письма: `Тема: ` + `render.Subject` + пустая строка + тот же текст, что `render.Digest`.
- Лимиты `render.DigestLimit` (4000) и `render.PostLimit` (2000). Сигнатуры из раздела 5 не принимают config, поэтому значения из `config.yaml` сюда не читаются.
- Повтор модели при длинном тексте ровно один. Дальше обрезка детерминированная: лишние предложения с конца, затем префикс поля до пола. Начало сути и все источники остаются.
- Деградация без модели и проверка фактов - это S8, здесь их нет.

## Открытые вопросы

- Роль `author` и `unknown` сейчас «СМИ». В комментарии `SourceRef` только три роли: первичный источник, СМИ, перепечатка.
- Нет `PublishedAt`: в дате пишется «дата не указана».
- Роль стоит в скобках у названия. В примере раздела 6.1 скобок нет, но задача просит показать роль первичного источника, не ломая поля «название, дата, URL, ID».
- `check_digest.py` организаторов в репозитории нет. Формат сверен с разделом 6.1 и `render.CheckFormat`.

## Передачи второму участнику

- В `main` на момент этапа есть S0-S3. Ветка `origin/s4-topic` в `main` не слита. S7 её не вызывает и пакеты A не меняет.
- В раннер: выбранные события передать в `summarize.Items`, из них собрать `DigestModel` (период, контрольное время, `Shortfall`, `Empty`), затем `summarize.ShortItems` и `render.Post`. `retryHints` - карта ID события на список замечаний.
- Причину недобора писать в `Shortfall` без префикса «Подходящих событий за период нет»: префикс добавляет рендер. Для пустого выпуска поставить `Empty` или пустой `Items`.
- Статьи только контекста (вне периода) в `ArticleIDs` не класть: иначе они станут строками «Источники». `ContextArticleIDs` рендер сам не читает.
- `NotIncluded` живёт в модели и журнале. В `digest.md`, пост и письмо оно не выводится.
- `Event.Rationale` должен быть одним предложением по сведениям публикаций. Иначе в «Обоснование» попадёт заглушка.
