# S11a: Mailer, API и веб на интерфейсе раннера

Владелец: B
Статус: выполнен
Ветка / коммит: s11a-api-web / S11a: add mailer, API, and web on the fake runner

## Сделано

- `internal/runner/fake`: `Runner` копирует подготовленный прогон из `testdata/fake_run/` в `OutDir` и сообщает прогресс по этапам `load` ... `verify`, `write`. `ExtraPaths` сохраняются в состоянии, текст выпуска остается фикстурой.
- `internal/api`: `POST /api/v1/runs`, `GET /runs/{id}`, `/digest`, `/post`, `/email`, `/journal`, `/report`, `/export`, `POST /runs/{id}/send`, `POST /runs/{id}/articles`, `GET /healthz` и `GET /api/v1/healthz`. Запуск асинхронный, состояние в памяти и в `runs/<run_id>/`. Раннер передается в конструктор.
- `internal/mailer`: SMTP из env через `config.Mail`, dry-run по умолчанию, allowlist, `net/mail`, лимит 10 адресов, дедупликация, MIME multipart (text + html), журнал отправки без секретов. Адрес вне списка дает 403 и строку в лог.
- Получатели берутся только из поля `recipients` или, если оно пустое, из allowlist. Текст публикации и лишние поля JSON на список не влияют.
- `web/index.html` и `web/app.js` встроены через `web/embed.go`: запуск, прогресс, вкладки, выгрузка, тестовая рассылка, добавление публикации.
- `cmd/digestd --fake`: сервер на `DIGEST_ADDR`, graceful shutdown. Без флага процесс сообщает, что реальный раннер подключается на S11b.
- ZIP: `digest.json`, `digest.md`, `post.txt`, `email_preview.html`, `journal.csv`, `run_report.json`, а также `email.txt` и `journal.json`, если они есть.

## Как проверить

```
go test ./internal/api/... ./internal/mailer/...
go vet ./...
go test ./...
DIGEST_ADDR=127.0.0.1:18081 ALLOWED_TEST_RECIPIENTS=jury@example.com go run ./cmd/digestd --fake
```

В браузере: путь `testdata/synthetic/articles.json`, контрольное время `2026-11-07T12:00:00+03:00`, запуск, вкладки, «Выгрузить», «Разослать (тест)» с dry-run. Адрес вне allowlist показывает ошибку и в API возвращает 403.

## Нюансы для следующих этапов

- `digest.json` API создает сам, если раннер его не записал: `period`, `control_time`, `shortfall`, `empty`, `text` (текст `digest.md`), `events` (поля `DigestItem`, включая `sources`). Если файл уже есть, он не перезаписывается.
- После прогона API записывает `run_report.json` еще раз и ставит `run_id` равным id HTTP-прогона.
- Fake не читает добавленную публикацию. `POST /runs/{id}/articles` создает новый `run_id` и передает прежний набор плюс `ExtraPaths`. Текст фикстуры не меняется. Реальный раннер на S11b должен обработать `ExtraPaths`.
- Пустой список получателей означает allowlist из конфига. Явный адрес вне списка отклоняется и в dry-run.
- Контрольное время без пояса разбирается как МСК (`timeutil.ParseDate`, политика `assume_msk`).
- Слушать сервер без `--fake` нельзя: S11b подставляет `runner.New`.

## Изменения контрактов

Нет. `internal/domain`, `internal/config`, `config.yaml` и `Makefile` не менялись. Интерфейс `runner.Runner` не менялся.

## Открытые вопросы

- Схема `digest.json` в ТЗ не задана. Взят объект с периодом, текстом выпуска и событиями (`events` = `DigestItem` с источниками).
- Лимит адресов в замороженном конфиге отсутствует. Сейчас 10 (`mailer.MaxRecipients`).
- Пустой `recipients` трактуется как «отправить на allowlist», а не как ошибка.

## Передачи второму участнику

- Пакеты участника A не менялись. `internal/runner` кроме нового пакета `runner/fake` не трогался.
- S11b: в `cmd/digestd` собрать `runner.New` без флага `--fake` и оставить fake под флагом. Каталог результата раннера уже совпадает с файлами API, кроме `digest.json`: его дописывает API из `RunState.Digest` и `digest.md`.
- Реальный раннер не шлет прогресс этапа `write` (только длительность в отчете). Fake этот этап показывает. UI рисует те имена, которые пришли.
- `POST /runs/{id}/articles` кладет файл в `runs/<new_id>/input/` и передает полный путь в `RunParams.ExtraPaths`. Набор исходного прогона не копируется, используется тот же `DatasetPath`.
