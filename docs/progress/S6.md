# S6: Оценка, ранжирование и выбор

Владелец: A
Статус: выполнен
Ветка / коммит: s6-rank / S6: score events and select the digest

## Сделано

- Промпты `score_event` и `rationale`. Оценки 0-3 по последствиям, масштабу, срочности и релевантности для руководителей и специалистов по ИБ организаций РФ. Нет сведений: `value=null`, пустая цитата и пометка «нет данных». Ноль только если текст прямо говорит, что эффекта нет. Позиция в поиске во вход не передается.
- `rank.Score` проверяет цитату (после схлопывания пробелов она должна быть фрагментом заголовка или текста статьи события) и диапазон 0-3. Иначе оценка становится `nil`, в `Evidence` не попадает. `Total` - среднее по весам известных оценок: пропуск не входит ни в числитель, ни в знаменатель. Настоящий ноль балл снижает. Если хоть одна оценка `nil`, в трассу пишется «часть данных неизвестна».
- Обоснование - одно предложение из последствий, масштаба и срочности. Если модель пишет про важность, поисковую выдачу, несколько предложений или молчит о пустой опоре, предложение собирает код из полей публикаций. Пустая опора явно называется: «сведения о последствиях не приведены», «сведения о масштабе не приведены», «сведения о срочности не приведены».
- `rank.Select` сортирует по `Total`, затем по числу независимых источников, затем по более поздней публикации статей события, затем по ID. Берет не больше лимита. У выбранных `Rank` от 1, у остальных `Rank` 0. Входной срез не переставляет.
- `rank.ApplyJournal` ставит первичной статье выбранного события «включён» и обоснование, остальным статьям выбранного события «объединён». Статьи только невыбранных событий - «исключён», `lower_priority`, место и балл. Группа сохраняется. Другие события той же статьи дописываются в причину. Статьи контекста не трогает.
- Сбой одного вызова не останавливает этап: событие остается с нулевым баллом или уже посчитанными оценками, текст ошибки лежит в `Result.Errors`. Пустой список событий не ошибка.

## Как проверить

```
go test ./internal/rank/...
make vet test
```

На одинаковых входах `Score` и `Select` дают один и тот же балл и порядок. Пропуск оценки не занижает балл, ноль занижает. Подмененная цитата, значение вне 0-3 и пометка «нет данных» сбрасывают только свою оценку. Меньше пяти событий выбираются все. Пустой список возвращается без ошибки. Шестое событие получает причину «Уступило по приоритету: место 6 из 6, балл ...». В промптах нет длинного тире.

## Нюансы для следующих этапов

- Порядок для раннера: `Score` (или `ScoreResult`), затем `Select(events, arts, cfg.Rank.MaxEvents)`, затем `ApplyJournal(journal, selected, result.Errors)`. `Score` сохраняет порядок входа. Место в журнале - это позиция в срезе после `Select`, а не поле `Rank`: у невыбранных `Rank` равен 0.
- `Select` принимает карту статей. В подписи раздела 5.7 ее нет, но без даты публикации тай-брейк не посчитать. Статьи контекста в дату не входят.
- `Event.Rationale` - одно предложение без метки «Обоснование:». Метку ставит рендер. В текст дайджеста этот этап ничего не пишет, в том числе пояснение при числе событий меньше пяти.
- Ключи `Scores.Evidence`: `impact`, `scale`, `urgency`, `relevance`. Значение - исходный фрагмент статьи. `nil` в оценке значит «нет данных», это не ноль.
- Флаг пишется фразой `rank.UnknownDataNote` («часть данных неизвестна») в трассу стадии `rank`. Туда же попадает `extract.WithNoter`. Повторная запись есть и в `ApplyJournal`, чтобы флаг был в журнале и без нотера в контексте.
- Статья, которая входит и в выбранное, и в невыбранное событие, остается у выбранного. Если статья входит в несколько событий, в причине будет «Также события: ...».
- Ошибка модели попадает в колонку `error`, только если там еще пусто. Иначе она дописывается в трассу, старый текст ошибки не затирается.
- Порог длины входа берется из `config.Default().LLM.MaxInputChars`, не из загруженного файла. В `Score` передается только `config.Rank`.

## Открытые вопросы

- Границы оценок 1, 2 и 3 заданы в промпте `score_event` как локальная шкала. В замороженном конфиге для них нет полей. Если на учебном наборе шкала окажется слишком грубой, ее можно поправить в промпте, не меняя контракт `Scores`.
